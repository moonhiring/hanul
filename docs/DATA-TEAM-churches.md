# 한울(HANUL) 데이터 팀 — 한인교회 데이터 개선 과제

> 대상: 데이터 수집·검증 전담 에이전트
> 작성: 기술팀 / 2026-11-18
> 목표: 현재 churches 데이터(2,092건)의 **정확도 실패를 인정하고, 출처 중심으로 재구축**한다.

---

## 1. 배경 — 왜 실패인가

현재 `churches` 테이블 2,092건은 **Overture Maps 단일 소스**에서
"이름에 한글이 있거나 'korean' 토큰이 있는" 장소만 걸러낸 결과다.

**문제점 (사용자 검증으로 확인됨)**

- 캘리포니아의 대표 대형 한인교회들(예: Young Nak Presbyterian, Sa-Rang Community Church, Grace Korean Church 등)이 **통째로 누락**
  → 원인: 이 교회들은 영어 이름만 등록되어 있어서 필터에 안 걸림. 영어 이름만 보고는 한인 교회 여부 판별 불가
- 반대로 오수집도 존재 — 이름에 "korean"이 들어간 비한인 장소
- 일본 26건, 중국권 10건 등 지역별 편차가 심각 — 수집 방법론이 지역 커버리지와 무관

**결론: 지도 데이터에서 이름 패턴으로 추리는 방식의 한계. 정답지(교단·교파 공식 명부)가 먼저고, 지도 데이터는 좌표·연락처 보강용이다.**

---

## 2. 재구축 원칙

1. **출처 계층을 지킨다.** 아래 Tier 순서대로 수집하고, 하위 Tier는 상위 Tier의 보강(좌표/전화/웹사이트)으로만 쓴다.
2. **모든 레코드는 출처를 남긴다.** `source` 컬럼에 Tier와 출처명을 기록 (예: `denomination:pcausa`, `map:overture`). 출처 없는 레코드는 needs_human.
3. **발견(recall)과 정확(precision)을 분리해 측정한다.** 대형 교회(정답셋) 발견율과 무관 레코드 비율을 따로 보고.
4. **삭제하지 않는다.** 폐쇄·비한인 판정은 status만 변경. 기존 상태 기계(active/stale/likely_closed/not_korean/duplicate/needs_human)를 그대로 쓴다.
5. **대형 교회 정답셋으로 회귀 검증한다.** 아래 §5의 검증셋이 매 수집 배치 후 100% 발견되어야 통과.

---

## 3. 소스 계획 (Tier)

### Tier 1 — 교단·교파 공식 교회 명부 (최우선, 정답지)
한인 교회의 절대다수는 교단 소속이고, 교단은 공식 Find-a-Church를 제공한다.

| 소스 | 커버 | 방법 |
|---|---|---|
| 해외한인장로회총회(KPCA) 명부 | 미국 장로교 대다수 | 웹 명부 스크레이프/요청 |
| PC(USA) / PCA / PC(호주) Find-a-Church + Korean 필터 | 미국·호주 | 공식 검색 도구 |
| 미주성결교회, 미주한인침례총회, 연합감리교(UMC) 한인교회 명부 | 미국 | 각 총회 사이트 |
| 재일대한기독교회 명부 | 일본 | 공식 사이트 |
| 독일·유럽 한인교회 협의회 명부 | 유럽 | 협의회 사이트 |
| 캐나다한인교회협의회 | 캐나다 | 협의회 사이트 |
| 천주교 각 교구 한인성당 목록 | 전 지역 | 교구 사이트 |

→ 이 Tier만으로 대형·중형 교회의 recall이 확보된다.

### Tier 2 — 커뮤니티·포털 디렉터리 (보조 정답지)
- 미주중앙일보/한국일보 업소록의 종교 카테고리
- KMCA(한인교회협의회) 지역별 명부, 각 도시 한인회 종교 단체 목록

### Tier 3 — 지도 데이터 (보강용)
- Overture Maps(현 파이프라인 재사용) + OSM Overpass(`name:ko`)
- **역할**: Tier 1·2에서 확보한 교회의 좌표/주소/전화/웹사이트 매칭 보강 + Tier 1에 없는 소형 교회 후보 발굴(이 경우만 신규 후보로 인정)
- 현행 "korean 토큰 필터"로 바로 적재하는 방식은 **폐기**

### Tier 4 — 각 교회 공식 웹사이트
- 예배시간(worship_times), 주소 확정, 목회자/연락처, 폐쇄 여부 신호 수집
- DeepSeek LLM으로 페이지 텍스트에서 예배시간 구조화 (기존 verify 워커 패턴 재사용)

---

## 4. 실행 절차 (배치 단위)

1. **지역 순서**: 미국(CA 먼저) → 캐나다 → 일본 → 유럽 → 오세아니아 → 동남아
2. 지역별로 Tier 1 명부 수집 → 정규화(이름/주소/전화/웹사이트) → overture_id·주소 기준 dedupe
3. Tier 3로 좌표·연락처 매칭 (이름 유사도 + 지오코딩 거리로 매칭, 불일치는 needs_human)
4. Tier 4로 예배시간·폐쇄 신호 수집
5. 적재: 기존 `api/scripts/load_churches.js` upsert 패턴 사용 (스키마 변경 최소화)
6. 배치 완료마다 §5 검증셋 회귀 테스트 + 지표 리포트

## 5. 검증

### 정답셋 (회귀 테스트 — 매 배치 후 자동 체크)
아래 교회들이 DB에서 이름 검색으로 발견되어야 한다. **100% 발견이 통과 조건.**
하나라도 빠지면 해당 배치는 실패로 기록하고 원인을 리포트한다.

미국 (CA 중심):
- Young Nak Presbyterian Church (LA)
- Sa-Rang Community Church (Anaheim)
- Grace Korean Church (Fullerton)
- Oriental Mission Church (LA)
- Berendo Street Baptist Church (LA)
- 풍성한교회 (Sunny Central?)
- 남가주사랑의교회 (Anaheim)
- ANC 온누리교회 (Fullerton)

→ 이 목록은 확정 전 기술팀·사용자와 함께 보강한다. 지역별(뉴욕/토론토/시드니/런던/도쿄)로도 5~10개씩 만든다.

### 지표 (배치 리포트에 포함)
- 정답셋 발견율 (목표 100%)
- 지역별 건수 분포 (인구 대비 이상치 표시 — 예: CA가 뉴욕보다 적으면 이상)
- 출처별 레코드 수 (Tier 1 출처 비율이 높을수록 좋음)
- needs_human 비율과 사유 분포
- 무작위 20건 사람 표본 검토의 정확도

### 데이터 상태 기계 (기존과 동일)
`pending → active / stale / likely_closed / not_korean / duplicate / needs_human`
- LLM의 not_korean·duplicate 판정은 자동 확정 금지 → needs_human 검토 큐
- 공개 API는 archived·not_korean만 숨김

## 6. 인터페이스 (기술팀과의 접점)

- **코드 위치**: 수집기는 `data-pipeline/`, 적재기는 `api/scripts/`. 기존 `extract_korean_churches.py`, `load_churches.js` 패턴 준수
- **스키마**: `churches` 테이블 그대로 사용. 컬럼 추가가 필요하면 HANDOFF.md에 먼저 메모 후 마이그레이션 스크립트로 제안
- **적재 실행**: 적재 명령은 서버 BOT이 수행 — 데이터팀은 CSV/스크립트와 "실행해 달라"는 명령 블록을 HANDOFF.md에 남김
- **git**: main 직접 push 가능하나, **기술팀·디자인팀 파일은 건드리지 않는다** (`app/src` 디자인, `api/src` 서버 로직). 커밋 전 `git status --short`로 자기 파일만 add. `git add -A` 금지
- **보고**: 배치 결과는 `docs/data-reports/`에 마크다운으로, HANDOFF.md에 한 줄 요약 추가
- **비밀값**: API 키 등은 커밋 금지. `.env` 파일 패턴 사용
